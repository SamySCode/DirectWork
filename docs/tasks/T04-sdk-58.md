# T04: Expo SDK 58 and over-the-air updates

**Model:** Opus (or Sonnet, with a review by the strongest model before
committing). **Size:** one or two sessions. Do it on its own branch from
a clean tree.

## Why

SDK 58 fixes the one advisory that can be triggered in the shipped app
(`decode-uri-component`, through expo-router). The allowlist in
`.github/audit-allowlist.json` expires on 2027-01-31, after which CI
fails. `expo-updates` must be in the first store build, or later fixes
cannot be sent without a new store release.

## Do

1. Read the Expo SDK 58 changelog and upgrade guide (web) before
   touching anything. Note breaking changes that affect expo-router,
   expo-image, expo-secure-store, expo-print, expo-sharing and typed
   routes.
2. `npx expo install expo@^58 --fix`, then `npx expo-doctor`.
3. Fix type errors and failing tests. `scripts/generate-route-types.js`
   resolves `@expo/cli` from inside the expo package; check it still
   works.
4. `npx expo install expo-updates`. Set `runtimeVersion` (policy
   `appVersion`) and the update URL placeholder in `app.json`, and add
   update channels to `eas.json` for preview and production.
5. Remove the allowlist entries the upgrade fixes, then run
   `npm run audit:prod`.
6. Build the web export with `npm run build:web` and confirm the
   Content-Security-Policy still passes (zero violations on a few
   screens).

## Don't

Never `npm audit fix --force`. Don't change app behaviour. Don't edit
migrations.

## Done when

`npm run check`, `npm run test:functions`, `npm run audit:prod`,
`npx expo-doctor` and `npx expo install --check` all pass, and you have
listed anything that can only be verified on a real device build.
